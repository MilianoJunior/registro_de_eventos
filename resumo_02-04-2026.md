## O que foi feito no project_03

### 1. PCH PIRA — Variáveis de Status das UGs

**Problema:** A PCH PIRA tem 5 UGs mas nenhuma variável de estado (UP, UPGM, UPS, UMD, US) estava configurada no `usinas_dispositivos.json`.

**Investigação:**
- Registradores extraídos do arquivo `config/UG-01.py`
- Criado `config/teste_status_pira.py` para validar leituras via API (`http://100.93.197.110:8010`)
- Confirmado que a PCH PIRA usa **lógica ativa-baixa** (False = estado atual), inverso das outras usinas
- `UMD` se chama `UMVD` no CLP da Pira (registrador `17109`) — tratado como UMD no sistema

**Registradores adicionados (mesmo endereço em todas as UGs, cada uma tem IP próprio):**
| Estado | Registrador | Tipo |
|--------|-------------|------|
| UP (parada) | 17099 | BOOLEAN, offset 0 |
| UPGM (pronta para giro mecânico) | 17104 | BOOLEAN, offset 0 |
| UPS (pronta para sincronização) | 17114 | BOOLEAN, offset 0 |
| UMD (marcha desexcitada) | 17109 | BOOLEAN, offset 0 |
| US (sincronizado) | 17118 | BOOLEAN, offset 0 |

**Arquivos alterados:**
- `config/usinas_dispositivos.json` — 5 registradores adicionados em UG-01 a UG-05 da PCH PIRA (PSA ignorado)
- `libs/servicos/coletor_core.py` — exceção em `_determinar_status()` para lógica invertida da Pira:
  - Se todos os estados operacionais (US, UMD, UPS, UPGM) são `False` → retorna `"UP (parada)"`
  - Caso contrário → primeiro `False` na ordem de prioridade = estado atual

## Problemas Identificados (para próximas sessões)

### Pendências conhecidas
1. **N+1 em `convert_id_to_name`** — chamada ~30x por requisição no `read.py`. Deveria ser uma única query com `IN` ou JOIN.
2. **PSA da PCH PIRA não lê níveis** — os nomes das leituras (`nivel_camara_carga`, `nivel_barragem`, `nivel_jusante`) não estão em `NIVEL_RESERVATORIO_LABELS` no `coletor_core.py`. Precisam ser adicionados ou os nomes no JSON precisam ser padronizados.
3. **MTTR volátil** — reinicia com o processo. Planejado: tabela `op_kpi_mttr` com cálculo diário a partir de `op_ocorrencia`. Deixado para depois pois há implementações maiores prioritárias.
4. **`google-generativeai` fora do `requeriments.txt`** — módulo `ai_generation.py` vai quebrar em ambiente limpo.
5. **`DEV_RELOAD` hardcoded como `True`** — watcher de arquivos sempre ativo, mesmo em produção.

### Contexto técnico importante
- Relé S700 da Schneider (PCH Pira) permite apenas **2 conexões simultâneas** — IHMs já ocupam essas conexões, então as temperaturas das UGs pela Pira **não são lidas via relé** atualmente.
- A lógica de status da Pira é invertida porque o CLP usa active-low (False = estado ativo), diferente de todas as outras usinas.
